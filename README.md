# DUYLORE Telegram Mini App – starter source

This is a starter implementation for a Telegram Mini App storefront selling digital keys.

## Included
- Telegram bot `/start` with Mini App launch button
- Dark purple responsive storefront
- Telegram Mini App `initData` validation on the backend
- Product catalogue and stock counts
- Telegram Stars invoice creation (`XTR`)
- Payment confirmation and automatic key delivery in bot chat
- Minimal password-protected admin API/page
- Inventory import and promo-code creation endpoint

## Important payment rule
Digital goods sold inside Telegram bots or Mini Apps must be paid using Telegram Stars (`XTR`). This starter therefore does **not** implement bank QR top-ups or a VND wallet inside Telegram. See:
https://core.telegram.org/bots/payments-stars

A separate website outside Telegram may have a separate checkout, but do not use it to bypass Telegram's in-app digital-goods payment rules.

## Requirements
- Node.js 20+
- Express (included in package dependencies)
- A Telegram bot created with @BotFather
- Public HTTPS URL for production

## Run locally
1. Install Node.js 20 or newer.
2. Copy `.env.example` to `.env`.
3. Fill `BOT_TOKEN`, `BOT_USERNAME`, `PUBLIC_URL`, and a strong `ADMIN_PASSWORD`.
4. Install dependencies: `npm install`
5. Start: `npm start`

For local Telegram testing, expose the local server through a trusted HTTPS tunnel and set `PUBLIC_URL` to that HTTPS URL. Do not publish your bot token.

## First setup
1. Open `@BotFather`, create a bot with `/newbot`.
2. Set a bot username.
3. Set the Mini App URL using BotFather's Mini App / menu button settings, or use the bot's `/start` button after the server is running.
4. Open `https://YOUR_DOMAIN/admin`.
5. Enter `ADMIN_PASSWORD`.
6. Create products and add inventory keys (one key per line).
7. Open the bot in Telegram and test with a low-value Stars product.

## Before real launch – required hardening
This is a development starter, not a production-certified payment system. Before accepting real customers:
- Add proper admin login sessions, rate limits, CSRF protection, audit logs and role permissions.
- Add atomic stock reservation/locking and idempotent payment processing; test simultaneous purchases and duplicate updates.
- Add refund handling via `refundStarPayment`, receipts, terms, privacy notice, and customer support workflow.
- Add promo-code redemption/discount calculation and tests (the starter currently stores promo definitions but does not apply them at checkout).
- Back up SQLite and move to managed PostgreSQL for multi-instance deployment.
- Use HTTPS, firewall, secret manager, monitoring, and regular backups.
- Have a qualified developer review payment, inventory, security, and applicable local legal/tax requirements.

## Database
SQLite database is created at `data/duylore.sqlite` on first run. It is excluded from Git.

## Quick cloud test (Railway)
1. Push this project folder to a private GitHub repository.
2. In Railway, create a new project and deploy from that GitHub repository.
3. Add a persistent volume mounted at `/app/data` so the SQLite database survives restarts/redeploys.
4. Add environment variables from `.env.example` in Railway Variables. Set `PUBLIC_URL` to the Railway HTTPS domain after generating it.
5. Set the service start command to `npm start`.
6. Once deployed, open `https://YOUR-RAILWAY-DOMAIN/admin` and use the `ADMIN_PASSWORD` to add a test product and its test key.
7. In BotFather, set the bot's Menu Button / Mini App URL to the Railway HTTPS domain, or use the `/start` web-app button generated by this app.
8. Test only with a non-sensitive dummy key and a low-value Telegram Stars price.

Do not add your `.env`, bot token, or real customer keys to GitHub. This project is a prototype; complete the production-hardening checklist before accepting real payments.
